# 用真实成功修正训练无提示模型

这项独立小试测量成功修正的学习价值。同一个 7B 模型借助同题失败记录找到的满分响应，能否成为有效示范，使普通策略在新题上更容易完成任务？上一轮 WebShop 试验中，带建议的后四条救回 4/16 题，普通后四条救回 0/16 题，但救活组贡献给 AdamW 的梯度范数最高为 $3.52\times10^{-16}$。[前一轮实测](../../outputs/fgpo-feedback-pilot-20261118/RESULTS.md)

## 标记步的学习目标

记 $h$ 为当前尝试的普通公开前缀，$D$ 为同题前一条尝试的公开记录，$q_D(y\mid h)$ 为在本步看过建议后生成完整响应 $y$ 的分布。建议只作用在这个环境步。之后模型用普通历史继续，$Y\in\{0,1\}$ 是这次真实尝试的官方终局结果。定义 $s(h,y,D)=\Pr(Y=1\mid h,y,D)$，对训练分布中的 $h,D$ 分别考察

$$
\mathcal L_h(\theta)=-\mathbb E_{y\sim q_D,Y}[Y\log\pi_\theta(y\mid h)].
$$

只要成功概率 $r=\Pr_q(Y=1\mid h,D)>0$，上式就是 $r$ 乘以成功响应条件分布 $q_D^+(y\mid h)=q_D(y\mid h)s(h,y,D)/r$ 与普通策略的交叉熵。$r=0$ 时原式自然为零。训练的是成功响应在无提示输入下的似然。它是一个明确定义的示范学习目标。原无提示期望成功率的改善要由独立任务实测。

还有一个局部性质。固定 $h,D$ 和后续普通策略，对理想的 $q_D^+$ 有 $\mathbb E_{q_D^+}s-\mathbb E_{q_D}s=\operatorname{Var}_{q_D}(s)/r\ge0$。这里的参照是产生示范的提议分布。有限数据中的一个共享模型只看 $h$，而训练和测试又会访问不同前缀，所以这条等式不能替代无提示模型的真实评测。

前四次已经出现成功时，余下四次普通采样，混合组使用现有 F-GPO。前四次全部失败时，余下四次在同一预先选定的环境步使用建议。只对实际走到该步并在终局满分的目标槽，累加该步完整响应在普通前缀下的负对数似然，包含实际生成的思考、动作和终止 token，每组仍除以 8。该分支只有来自官方成功的示范项。未达到标记步的轨迹仍计入采样分母。带建议后再由普通模型生成的后缀访问了不同的状态，且前四条和后四条通过建议相关联，因此这里单独处理整个触发组。部分得分用于分析购买质量。 普通分支沿用 V4 的算子。按前四条的结局选择分支也会改变所见组的分布，整个新训练过程的效用仍以无提示成绩衡量。

零示范梯度对照用同一批响应、相同计算图和相同优化器步数，把示范梯度乘零后执行实际 AdamW。这样可以区分新梯度、旧动量、偏差修正与权重衰减的作用。两臂共享普通混合组的参考数据、优势、处理顺序和原有 PPO 设置。标记步目标没有概率上限、密度比阈值或负例比率截断。

## 输入和历史信用的独立比较

WebShop 的候选投影去掉原生环境判为无效的搜索按钮点击，保留带关键词的搜索，并在每轮说明输出契约。AppWorld 的投影将闭合的思考文本与唯一非空 Python 代码块分开，格式、语法不满足契约时向模型返回具体原因。合法代码仍交给原生环境。此举会改变模型所见反馈，需要用真实执行数据评价。

历史信用保留既有的同深度、整轨迹留一和支持半径。WebShop 与家务环境对纯观测 token 做精确比较，AppWorld 沿用局部观测余弦。冻结参考模型的一次因果前向同时取状态末位和过去已执行响应的闭合位。对 $t$ 之前的闭合位求均值后归一化，随轨迹累计，空历史以与非空表示正交的单位符号表示。沿用已有支持定义，两种历史表示都在原邻域内才有共同支持。这个选择表达的是一个可实测的匹配假设。覆盖量、同一批目标上的留一预测误差和任务成绩分别报告。

## 预定比较

**Colab 基础模型独立小试。** 三种方法从同一份未经 WebShop 训练的 Qwen2.5-7B-Instruct 和空 AdamW 状态出发，沿用 V4 公开输入。对原清单的 32 道训练题只采一份轨迹库。每题保留八条普通轨迹，前四条全败时额外保留同题、同槽种子的四条带建议重试。三种更新按各自规则从同一库中取样，以实际的混合组和满分救回事件决定更新次数。无提示评测固定为原预留 32 题，每臂每题一次。主要读数是相对普通 V4 新增和失去的满分题数及其净差，辅助读数是原生 Score 的配对均值差。若有 $E$ 道题的普通前四条全败，这次小试的完整轨迹数为 $256+4E+96$，上限 480。旧 WebShop 终态模型的 9、12、13 次更新与旧成绩单列。独立小试检验这三条完整训练规则在基础模型起点的表现，反馈触发时机的独立作用需要等步数对照。

Colab 上传前一个任务的检查点时，GPU 计算空闲，驱动可用显存实测为 22.3 GiB。这次冻结采样在一个独立进程里逐槽执行，每个完成的槽位单独保存，采样进程实际采用的 PyTorch 分配器上限为 19.75 GiB。每题仍按既定四个槽位判定是否需要建议，物理分批对整批训练题一致。三种方法共享这份语料，各自在原任务释放 GPU 后执行参数更新。[同时上传和采样的资源记录](../../outputs/fgpo-colab-956ceab-ag-20261116/base_qwen_webshop_32/simultaneous_upload_and_collect_proof.json)

用户在前三臂评完后要求补测无门限方案。补充臂从同一基础 Qwen 和空 AdamW 出发，共用零示范对照的固定参考和 9 个普通 PPO 组，在相同的 3 个触发位置对 4 条真实满分的标记响应施加既定成功似然损失。补充比较单独输出，与普通 V4、零示范梯度逐题对齐相同的 32 题。四臂使用 348 条采样和 128 条评测，合计 476 条。

WebShop 两臂使用相同 7B 起点、原始冻结参考、优化器、任务和逐题随机种子。先前 48 题作为开发面板，另预定 32 个去重的训练区任务 ID 作新面板。两者均独立于本次训练组，正式 benchmark 终评仍由既定协议承担。AppWorld 的三步读数衡量局部执行行为，家务环境的读数衡量同伴信用。二者各自的适用范围与 WebShop 的无提示成绩分别报告。

## 对原分析的修订

**保留正式二值目标。** 始终获得 2/3 分的策略，按满分率排在一半满分、一半零分的策略之后，按平均得分却排在前面。这个两策略反例直接说明改用部分分会改变目标排序。鞋码轨迹同时改变了颜色、尺码及选购商品，单凭这组总分无法识别某一点击的因果价值。固定版本的上游 WebShop 适配也只在终局满分时给予环境正奖励。作者训练器的格式或无效动作项应单独记账。[上游代码](https://github.com/langfengQ/verl-agent/blob/20bd331/agent_system/environments/env_package/webshop/envs.py#L42-L48)

**统一各项数字的分母。** WebShop 按 16 个任务簇估出的波动与实际轮间波动相近，任务和权重却同时改变，因此没有已识别的方差归因比例。WebShop seed 0 的 271 次裁剪前范数全范围约为 9.97–1,190.55。首个混合组的采样和重新评分之间，按 token 加权的平均绝对 logprob 差为 0.00548。理论上的初始比率为 1，数值回放存在偏差。家务任务完整 60 轮中，格式有效为 141,358/152,824（92.50%），可行动作有效为 124,003/152,824（81.14%）。两者及每步响应总长度都需要和真正的思考 token 长度分开。全败组跳过本组更新是 V4 的代数性质。其他任务仍会改变共享参数，跨整个训练过程陷入死锁则需要持续的运行证据。[V4 训练原件](../../outputs/fgpo-colab-956ceab-ag-20261116/gdrive_staging/comparison/alfworld/fgpo/seed-0/training.jsonl)

**接口错位有直接证据，跨任务因果归因要另测。** WebShop 的系统提示本已要求先简洁思考再输出唯一动作，家务任务和 WebShop 共用文本解析器。按同一份 AppWorld 四组 2,240 步原件解码，至少四个围栏定界符为 1,418 步，输出正好 1,024 token 为 747 步，其中 746 步未以指定终止符结束。最后一个原生 `Message:` 行以 `unterminated string literal` 起头的有 1,278 步，不能从错误名直接断定全由英文撇号造成。另有 77 步虽被记录为原生有效，送入的却是空程序。新接口应同时报告真正送入并有效执行的非空代码。先前的 861 步统计相邻两次出现相同原始反馈，未要求是同一种语法错误。过滤前置解析会改变代理看到的反馈及后续动作分布，这正是活体对照要测的作用。[AppWorld 旧轨迹复算](../../outputs/fgpo-verified-feedback-20261118/app_archive_reparse.json) · [现行解析器](../../src/fgpo/public.py)

**原标记步的正负门限可能使更新方向反转。** 取单步两动作，普通策略对两动作各取 0.5，提示策略以 0.9 选动作 $a$，真实成功概率分别为 0.49 和 0.51。用准确基线 0.5，$A=Y-0.5$。按原分析所写的正对数似然项、负项截断比率和 $\eta=0.2$，两个正项都在门内，负例对 $a,b$ 的系数分别为 $5/9,1$。对动作 $a$ 的 logit，期望上升方向是 $+0.046$，真实成功率梯度却是 $0.25(0.49-0.51)=-0.005$。原式中最小分母与最大概率阈值也给出不同目标，PPO 裁剪与采样 k3 惩罚均不构成概率的硬边界。V-trace 还包含跨步比率和时序差分。当前小试完整撤下这个门限并显式定义似然目标。[V-trace 原文](https://proceedings.mlr.press/v80/espeholt18a.html)

**匹配率与动量分别需要单独对照。** 86.08% 的 WebShop 混合组步找到同伴，描述支持覆盖，无法据此读出错规格匹配的比例。在已经保存的 9 个普通混合组内，根节点之后有 993 对同深度轨迹具有完全相同的纯观测，其中 311 对经历了不同的先前动作，63 对连紧邻的上一动作也不同。这个结果确认了可供区分的历史，尚未标注哪些同伴的真实续值匹配错误。取两个距离的最大值会缩小支持，实际误差要另测。此前动作表示属于动作前信息，但第一批的动作与成败会决定第二批有无引导，原本独立的同伴采样假设在这种自适应组中不自动成立。当前试验只在普通分支沿用 V4 的组信用。上次两条学习线在第 6、9、14 组三次普通更新已有数值差异，因此第 17 组的梯度变化不能唯一归因于第 16 组的旧动量。新的同时钟对照专门处理这项混杂。[纯观测配对计数](../../outputs/fgpo-verified-feedback-20261118/webshop_observation_pairs.json) · [原研究契约](../../docs/fgpo_math_contract.md) · [配对训练记录](../../outputs/fgpo-feedback-pilot-20261118/results.json)
