# F-GPO

Implementation of [F-GPO: filtration-DAG group policy optimization](docs/fgpo_design_and_derivation.md) on the installed official ALFWorld and AppWorld benchmarks. The active package is `src/fgpo`; existing benchmark assets, models and raw experiment results remain in place. Local work is static source editing. Root installs the complete implementation before the unified official study on the existing authorized servers.

The formal matrix uses all 134 ALFWorld valid_unseen tasks and all AppWorld test_normal (168) and test_challenge (417) tasks, with seeds 0/1/2. Horizons are 50/100. FGPO and its three own ablations use output limits 256/1024 and 60 rounds ×16 same-task groups ×8 independent trajectories. There is no old token/step/device/wall training budget, tier matrix or time-decayed utility. All external baselines retain their author configurations and actual workflows; Skill-DisCo runs its offline library workflow once. Native Qwen is frozen. Data/interface adaptations are recorded separately from method recipes. Faulty physical GPUs0/2 are excluded; occupied GPUs on HostA/B are eligible when their available memory accommodates the actual workload.

GiGPO and BiPACE_Q each retain the author window of 150 complete iterations. SELF retains its original optimizer, batch 16, LoRA and EMA recipe; Table 6 of its paper does not publish a numeric outer round count. Its explicit 60-round window here is this study's finite Qwen7B/ALF migration choice. Skill-DisCo has zero outer RL rounds and one actual offline induction/verification pipeline; frozen native Qwen has zero training rounds. Each trainable cell calls Engine.train once with its method-specific configuration.

The final FGPO conventions use packed s_ext including newly disclosed ALFWorld commands. The pure-observation window retains the initial block and recent complete blocks; the global goal-posterior frontier F persists across window changes. These are FGPO mechanism conventions, not changes to external author recipes.

The environment worker preserves official native initialization and `step_native` execution. Only public task instructions, bootstrap observations and actual returns enter actor histories. ALFWorld SR and AppWorld TGC/SGC are computed from official evaluator results, including complete official scenario membership. Each trajectory slot has its own process and working directory.

The server entry point is `python -m fgpo.runner --config configs/fgpo-qwen7b-official-20261116.json --output-dir outputs/fgpo-official-20261116 --gpu <physical IDs>`. With no method/benchmark/seed selectors it runs the complete configured matrix; each independent server process may own a disjoint subset using `--methods`, `--benchmarks`, and `--seeds`. Source installation uses `/apps/users/adminuser/fgpo-reproduction-20261116`; set `PYTHONPATH` to its `src` and use the configured existing Python. Root assigns healthy physical devices based on actual available memory. Each process exposes only its assigned physical cards through `CUDA_VISIBLE_DEVICES` with PCI bus ordering. Engine uses the corresponding local CUDA indices; saved cell config and dispatch metadata record both identities. Explicit resume consumes the saved checkpoint. The four-lane supervisor is `scripts/launch_fgpo_formal.py`; its read-only `--watch` follows actual process and result progress.

Fresh invocations require a new study directory. Add explicit `--resume` with the same study path to reuse completed cells with matching method/benchmark/seed/model identity and continue incomplete cells from their actual `checkpoint/CURRENT` state. Persisted official task lists and completed evaluation split summaries stay in place; Engine consumes its committed per-task rows and pending training/library state. Existing incomplete cells without a checkpoint stop with an error. Previously unstarted cells in the same resumed matrix start once. Managed interruption returns without running final evaluation; native frozen and completed Skill-DisCo work are reused through the same saved-state path. No automatic restart is scheduled.

Each cell saves its exact config, full official task lists, trained checkpoint, training summary, actual per-task evaluation rows, and per-split metrics. AppWorld TGC is the percentage of official tasks successful; SGC is the percentage of complete official scenarios whose tasks all succeeded. ALFWorld SR is official task success percentage. Missing official scores/tasks stay missing rather than becoming budget failures. Engine-owned physical cost and training logs supply the design's endogenous diagnostics without extra rollouts. External method windows and output limits are explicit in `method_configs`; FGPO outputs are256/1024 and existing external/native outputs512/1024. The shared official horizons and splits are interface/data adaptations, not claims of identical author recipes.

Incomplete training and evaluation keep the full resume checkpoint. Once all official splits finish, the cell retains its exact final model/adapters, RNG and reproduction metadata in `final_checkpoint`, publishes the complete summary, and reclaims that cell's unused optimizer/master/moment/reference resume files. Original results and cost journals stay in place. Prior-study checkpoints are preserved. A final model artifact supports evaluation reproduction; incomplete training resumes from the full checkpoint.
